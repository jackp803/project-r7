A local launcher must first identify the intended repository/worktree and verify that the user's existing Codex installation and authentication are available without printing credentials. It then submits the prompt using the locally installed supported interface and records an actual session/process identifier plus initial output. Do not infer dispatch from creating an issue or merging documentation.

Use existing local interactive Codex or `codex exec` with the user's approved sandbox/permissions. Check local `codex --help` / `codex exec --help` first; do not guess flags, bypass approvals, copy auth.json, or switch to API-key billing. No cloud execution fallback.
