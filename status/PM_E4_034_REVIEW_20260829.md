# PM Review — E4-20260829-034

## Decision

`NOT ACCEPTED / BOUNDED REMEDIATION REQUIRED`

E4-20260829-034 is not accepted for merge. The source/test-definition scope is otherwise bounded and executable verification remains correctly `NOT_RUN / NOT_PASS`, but static review found a positive-capability fail-open in the `REPO_EVIDENCED` path.

## Defect

`_fieldset_is_repo_evidenced()` verifies that:

- the caller-supplied fieldset equals the public resolver-owned expected descriptor;
- the caller-supplied hash equals the deterministic hash of that descriptor;
- `provider_fieldset_ref` and `provider_fieldset_generation_id` are merely non-null.

It does not bind the positive ENTRY / READ_ONLY_RECONCILIATION result to an E4-owner-authoritative immutable repository fieldset identity/generation. A caller can therefore copy the expected descriptor, recompute its public hash, supply arbitrary non-empty ref/generation values, and obtain `REPO_EVIDENCED` without possessing any owner-authoritative repository capability evidence.

That contradicts the active task requirement that positive capability use the exact current repository-evidenced field-set rather than caller-manufactured fields, and that caller material must not create capability authority.

The existing test fixtures reinforce the gap by constructing arbitrary `repo-fieldset:*` and `repo-generation:fp02-v0.1` strings without testing rejection of forged positive-row provenance.

## Required remediation

A fresh bounded E4 task must preserve all current unresolved/fail-closed provider semantics and change only the positive repository-evidence provenance boundary. At minimum:

- define or otherwise consume an E4-owner-authoritative immutable current repository fieldset identity for each positive row (ENTRY net_mode, ENTRY long_short_mode, READ_ONLY_RECONCILIATION), including exact ref/generation/hash/descriptor binding;
- positive `REPO_EVIDENCED` must require exact match to that owner-authoritative identity, not merely any non-null ref/generation plus a reproducible descriptor hash;
- forged/arbitrary ref, generation, descriptor, hash, or row/mode cross-use must fail closed with existing `OKX_SWAP_PROVIDER_FIELDSET_UNPROVEN` or another already-accepted E4-local reason; do not add a shared-contract enum;
- caller capability assertions remain rejected;
- PROTECTION_STOP / POSITION_EXIT / EMERGENCY_EXIT remain `UNRESOLVED_FAIL_CLOSED` with no provider-native mapping inferred;
- READ_ONLY_RECONCILIATION remains GET-only/default-deny and mutation-forbidden;
- add regression definitions proving a caller cannot manufacture `REPO_EVIDENCED` by copying the public descriptor/hash and inventing ref/generation;
- no provider transport/auth/private API, credentials, runtime, mutation, capital, shared contract, or GitHub CI changes.
