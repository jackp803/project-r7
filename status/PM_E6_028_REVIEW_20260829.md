## Confirmed integration defect

The new FP-11 restart/currentness read model compares the existing `paper_position_current_projection.payload_hash` and `paper_position_lifecycle_projections.payload_hash` against the canonical **Position** hash derived by `ProtectionRegistryCurrentAuthority`.

That is the wrong hash domain.

Existing authoritative E6 runtime persistence in `src/storage/_paper_runtime.py::_PaperRuntimeStore.persist_position_projection()` computes canonical `payload_hash` from the **lifecycle projection payload** and writes that same projection payload hash into both:

```text
paper_position_lifecycle_projections.payload_hash
paper_position_current_projection.payload_hash
```

Therefore the E6-028 `recover()` checks that compare those values to `current["position_hash"]` can falsely classify a correctly persisted current lifecycle projection as stale/conflicting after restart.

This is a static integration defect, not an executable-test failure. `NOT_RUN` remains `NOT_PASS`.

## Required remediation

A fresh E6 task must keep the current Position hash and lifecycle-projection payload hash as separate evidence domains.

At minimum:

1. derive/validate the exact canonical lifecycle-projection payload hash independently of the canonical Position hash;
2. require `paper_position_current_projection.payload_hash` to match the selected current lifecycle projection payload hash;
3. require the selected `paper_position_lifecycle_projections.payload_hash/payload_json` to match the exact current lifecycle projection supplied in authority;
4. continue binding FP-11 `position_hash` / intended-lineage `position_hash` to the canonical Position hash only;
5. add a regression fixture using the existing normal `_PaperRuntimeStore.persist_position_projection()` writer rather than hand-seeding a current-index hash with Position semantics;
6. preserve all existing fail-closed competing-head, FP-04 dependency, E5 interpretation, terminal-flat and no-mutation rules.

No shared-contract change is required by this defect. It is E6-owned persistence/read-model integration.
